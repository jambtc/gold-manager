# SIP-0065 — Go Worker Full Commentary Engine

| Field   | Value                 |
|---------|-----------------------|
| Status  | Accepted (Implemented) ✅ |
| Author  | Gold Manager Dev Tool |
| Created | 2026-05-20            |

## Summary

Il Go worker gestisce tutte le partite competitive ma genera solo
`goal`, `near_miss`, `gk_save`, `kickoff`, `half_time`, `second_half_start`.
Mancano tutti gli eventi necessari per una telecronaca apparentemente reale.
Questo SIP porta il Go worker alla parità con il PHP engine.

---

## Missing Events

| Tipo | Priorità | Note |

## Probabilità per Tick (90 tick totali)

```
Goal home:          ~2.5%   → ~2.25 gol a partita per squadra (calibrare)
Goal away:          ~2.5%
Near-miss home:     ~4%
Near-miss away:     ~4%
GK save home:       ~3%
GK save away:       ~3%
Corner:             ~2%     → ~1-2 corner a metà campo
Yellow card:        ~1.5%   → ~1-2 gialli a partita
Midfield duel:      ~15%    → ~13 azioni di centrocampo
Attack attempt:     ~10%    → ~9 conclusioni bloccate
(rest)              ~52%    → tick silenzioso (solo state broadcast)
```

## scorer_name in goal

Leggere il nome dal DB basandosi sull'attacco:
```go
scorerName := e.randomPlayerName(fixtureID, teamSide, "FW")
detail = fmt.Sprintf(`{"home_score":%d,"away_score":%d,"scorer_name":%q,"description":%q,"suspense_text":%q}`,
    hs, as, scorerName, fallback, suspense)
```

---

## midfield_duel e attack_attempt

Frase breve + `suspense_text` per tenere il ritmo della cronaca:

```go
case chance < 31.0: // midfield_duel
    eventType = "midfield_duel"
    teamSide = randSide()
    fallback = pick(["Fase interlocutoria a centrocampo.",
                     "Pressing alto, le squadre si studiano.",
                     "Palla recuperata a metà campo."])
    detail = fmt.Sprintf(`{"description":%q}`, fallback)
```

---

## corner

Dopo una `near_miss` laterale, ~30% chance di generare anche un corner:

```go
if eventType == "near_miss" && rand.Float64() < 0.30 {
    // insert corner event, broadcast
}
```

---

## yellow_card / red_card

Stessa logica del PHP (`resolveCards`) ma semplificata:
- 1.5% per tick per squadra → giallo
- 0.05% → rosso diretto
- Secondo giallo → rosso automatico (tracciare con counter in-memory)

Aggiornare `player.yellow_cards`, `suspended_matches` nel DB.

---

## injury

~0.05% per tick per squadra → infortunio su un giocatore casuale.
Aggiornare `player.injury_weeks`, `injury_type`.

---

## substitution (CPU)

Il Go deve applicare le sostituzioni dalla tabella `match_command`
(già scritte da `LiveActionController` per i manager umani)
e generare il proprio evento `substitution` nel log.

CPU teams: sostituzione automatica a 60' e 75' se giocatore con freshness < 60.
