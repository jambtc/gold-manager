# SIP-0021 — Go Match Worker (Live Engine)

| Field   | Value                     |
|---------|---------------------------|
| Status  | Accepted (Implemented)     |
| Author  | Gold Manager Dev Team      |
| Created | 2026-05-16                |

## Summary

The tick-based match engine currently runs as a PHP console command
(`game/run-fixtures`) suitable for development and CPU-vs-CPU simulations.
For production live matches with real-time spectating, this SIP mandates
replacing the PHP scheduler with a **Go micro-service**.

## Rationale

| Concern                  | PHP + cron        | Go daemon              |
|--------------------------|-------------------|------------------------|
| Long-running process     | Anti-pattern      | Native                 |
| Concurrency per match    | Process per call  | One goroutine per match|
| SSE / WebSocket streaming| Requires Swoole   | Native `net/http`      |
| CPU-bound tick math      | Adequate          | Fast                   |
| Docker image size        | ~300 MB           | ~8 MB (static binary)  |
| DB integration (MariaDB) | PDO               | `sqlx` / `gorm`        |

## Communication Contract

The two services communicate **only through the database**.
No direct RPC or HTTP calls between PHP and Go.

```
PHP/Yii2                             Go worker
─────────────────────────────        ──────────────────────────────────
Manager queues sub/tactic     ──DB──→  Reads match_state.pending_*_actions
                                       Advances tick, writes match_event
Frontend polls for events     ←──DB──  match_event rows are the source of truth
SSE endpoint (Phase 5)               Go streams match_event rows via SSE
```

## Planned Go Service Structure

```
gold-manager/
└── worker/
    ├── Dockerfile          # FROM scratch, ~8 MB final image
    ├── go.mod
    ├── main.go             # Entry point, scheduler loop
    ├── engine/
    │   ├── tick.go         # Tick resolution (translated from MatchEngine.php)
    │   ├── formation.go    # Formation & player totals
    │   └── character.go    # Character trait modifiers
    ├── db/
    │   └── queries.go      # Raw SQL queries (no ORM overhead)
    └── sse/
        └── server.go       # SSE endpoint for live match streaming
```

## Scheduler Logic (Go)

```go
// Every real second, check for fixtures that need a new tick
// (match_date + current_minute * 60 <= now)
// Then fan-out to goroutines, one per fixture.
func scheduler(db *sqlx.DB) {
    ticker := time.NewTicker(60 * time.Second)
    for range ticker.C {
        fixtures := db.ActiveFixtures()
        for _, f := range fixtures {
            go advanceTick(db, f)
        }
    }
}
```

## Docker Compose Addition (Phase 5)

```yaml
  go-worker:
    build: ./worker
    restart: unless-stopped
    environment:
      DB_DSN: "gm_user:secret@tcp(mariadb:3306)/gold_manager"
    depends_on:
      - mariadb
    networks:
      - internal
```

The `go-worker` container has **no exposed ports** except the SSE endpoint
routed through Caddy.

## Acceptance Criteria (Phase 5)

- [ ] `worker/` directory exists with buildable Go module.
- [ ] Scheduler advances all active fixtures every real minute.
- [ ] SSE endpoint streams `match_event` rows in real time.
- [ ] PHP `game/run-fixtures` is kept for development/testing only.
- [ ] `docker compose up` starts both PHP and Go containers cleanly.
