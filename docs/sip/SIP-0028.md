# SIP-0028 — Promotion & Relegation

| Field   | Value             |
|---------|-------------------|
| Status  | Accepted (Implemented) |
| Author  | Gold Manager Dev Team |
| Created | 2026-05-16        |

## Summary

At the end of each season, the top N managers of Serie C are promoted to
Serie B, and the top N managers of Serie B are promoted to Serie A. The
bottom N of Serie B are relegated to Serie C, and the bottom N of Serie A
to Serie B. CPU teams fill any vacated slots. This process runs inside
`economy/season-rollover` before standings are reset (see [[SIP-0027]]).

---

## Rules

| From | Promoted (top) | Relegated (bottom) |
|------|---------------|-------------------|
| Serie C → B | 1 per girone | — |
| Serie B → A | 1 per girone | 1 per girone → C |
| Serie A     | —            | 1 per girone → B |

Only **human-managed teams** are promoted/relegated. CPU teams are
replaced in-place by new CPU teams generated by `TeamSeeder` to keep all
gironi at full capacity.

---

## Algorithm

### Step 1: Serie C → Serie B

For each Serie C `competition` (girone):

1. Rank teams by points DESC, goals_for DESC.
2. The human manager at rank 1 (if any) is promoted.
3. Their team is moved: standing row transferred to a Serie B girone with
   a CPU slot (same group if available, fallback to first same-tier girone).
4. A new CPU team is seeded into the vacated Serie C slot.

### Step 2: Serie B → Serie A / Serie B → Serie C

For each Serie B `competition`:

1. Top-ranked human → promoted to Serie A (same group if available, fallback tier girone).
2. Bottom-ranked human → relegated to Serie C (joins a girone with a free
   CPU slot by same-group/fallback logic).
3. Vacated slots filled with new CPU teams.

### Step 3: Serie A bottom

For each Serie A `competition`:

1. Bottom-ranked human → relegated to Serie B.
2. Vacated slot filled with a new CPU team.

---

## Team Move Mechanics

Moving a team between competitions means swapping standing competition IDs
between one human team and one CPU team:

```sql
UPDATE standing SET competition_id = :target WHERE id = :human_standing_id;
UPDATE standing SET competition_id = :source WHERE id = :cpu_standing_id;
```

The team record itself does not change (name, players, budget, stadium stay);
only standing linkage is swapped.

Fixtures for the new season are generated fresh by `FixtureSeeder` after
all promotions/relegations are resolved (see [[SIP-0027]] §8).

---

## Notifications

After promotion/relegation, one manager news item is created per affected team:

- Promotion: `Promozione in {Serie B/A}`
- Relegation: `Retrocessione in {Serie B/C}`

Stored in `news_item` (`category=system`, icon ⬆️/⬇️, priority=1, link to classifica target).

---

## Edge Cases

| Case | Resolution |
|------|-----------|
| No human in a girone | No promotion/relegation for that girone |
| All target gironi full of humans (no slot CPU) | Nessuno swap applicato in quel rollover |
| Human at rank 1 AND rank last (only human in girone) | Promoted, not relegated |

---

## Acceptance Criteria

- [x] Top human in each Serie C girone is promoted to Serie B.
- [x] Top human in each Serie B girone is promoted to Serie A.
- [x] Bottom human in each Serie B girone is relegated to Serie C.
- [x] Bottom human in each Serie A girone is relegated to Serie B.
- [x] Vacated slots are filled with freshly seeded CPU teams.
- [x] Promoted/relegated teams retain all players, budget, stadium.
- [x] Notification created for each affected manager.
- [x] Process runs inside `economy/season-rollover` transaction before standing reset.
- [x] No promotion/relegation occurs if no human manager in a girone.
