# SIP-0087 — Always-On Market & Continuous Play

| Field    | Value                  |
|----------|------------------------|
| Status   | Accepted (Implemented) |
| Created  | 2026-06-02             |

## Problema

Il modello classico con finestre di mercato (estate/inverno) e off-season crea lunghi periodi
morti in cui il manager non può fare nulla di rilevante. In un gioco real-time asincrono
questo porta a churn: i giocatori smettono di connettersi durante i periodi "chiusi".

## Soluzione

**Mercato sempre aperto.** Nessuna finestra stagionale. I trasferimenti (acquisti, vendite,
prestiti) e le operazioni sullo staff sono disponibili 24/7.  
**Motore sempre attivo.** Non esiste off-season: alla fine di ogni stagione il calendario
del successivo viene generato immediatamente, senza pausa forzata.

### Impatto sul gameplay

- Il manager può acquistare rinforzi in qualsiasi momento, anche a campionato in corso.
- Le trattative diventano più tattiche: posso acquistare *ora* oppure aspettare che il
  prezzo scenda.
- Lo staff (allenatori, fisioterapisti, scout) può essere ingaggiato/liberato in ogni momento.
- Nessun "schermo vuoto" tra stagione e stagione.

## Implementazione

### PHP — TransferWindowService

- `isOpen()` ritorna `true` di default senza env override.
- Rimosso il branch `YII_ENV_DEV`; il comportamento dev diventa il comportamento di produzione.
- `GM_TRANSFER_ALWAYS_OPEN=0` permette ancora di ripristinare le finestre (opt-in legacy).

### Staff

- Nessun gate stagionale per hire/fire staff (già assente in `StaffController`; verificato).

### Motore partite

- SIP-0025 (League Expansion) genera il prossimo calendario immediatamente dopo
  il season rollover — nessuna pausa.
- `EconomyController::actionRunSeasonRollover()` avvia il seeding del prossimo
  calendario subito dopo promozione/retrocessione.

## Env

| Variabile                | Default | Descrizione                         |
|--------------------------|---------|-------------------------------------|
| `GM_TRANSFER_ALWAYS_OPEN` | *(unset = sempre aperto)* | `0` per ripristinare le finestre |

## Acceptance Criteria

- [x] `TransferWindowService::isOpen()` ritorna `true` senza env var.
- [x] `YII_ENV_DEV` non è più il gate per il mercato aperto.
- [x] Staff hire/fire non è bloccato da stato stagionale.
- [x] La UI del mercato non mostra più "finestra chiusa" in produzione (salvo `GM_TRANSFER_ALWAYS_OPEN=0`).
