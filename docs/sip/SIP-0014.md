# SIP-0014: Notifications and WebSocket Infrastructure

- Status: Accepted (Implemented)
- Type: Infrastructure
- Created: 2026-05-14

## Abstract

Define real-time communication infrastructure for user-facing notifications and live channels.

## Scope implemented in v2

- Live match updates via existing SSE hub (`/stream/{fixtureId}` on Go worker).
- Real-time notification badge in header for authenticated managers.
- SSE notification stream endpoint in PHP (`/notification/stream`).
- Poll fallback endpoint (`/notification/poll`) for browsers/network paths where SSE fails.

## Technology

- SSE (Server-Sent Events) as primary browser push channel.
- Polling fallback for resilience.
- Existing queue workers + NewsItem DB writes as event source.
- Telegram remains independent channel (not part of header live badge).

## Event examples currently surfaced by notification badge

- Transfer completed / offer outcomes.
- Friendly challenge updates.
- Match and injury/discipline updates.
- Finance/system updates (sponsor, rollover, etc.).

## API

- `GET /notification/stream`: `text/event-stream`
  - events: `news`, `ping`
  - payload: `{ unread_count, latest_id, server_ts }`
- `GET /notification/poll`: JSON fallback
  - payload: `{ ok, unread_count, latest_id }`

## Notes

- This SIP delivers real-time notifications without introducing WebSocket operational overhead.
- SSE chosen for lower complexity and alignment with existing live-match transport.
- For very high concurrency or bidirectional needs, a future SIP can add a dedicated WS broker.
