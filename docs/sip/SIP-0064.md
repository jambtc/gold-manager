# SIP-0064 — Live Attack Indicator Bar

| Field   | Value                 |
|---------|-----------------------|
| Status  | Accepted (Implemented) |
| Author  | Gold Manager Dev Team |
| Created | 2026-05-20            |

## Summary

Replace the static match progress bar with a dynamic **attack indicator**
that shows which team is in possession and how dangerous the action is.
The bar starts at center, moves toward the attacker's end on each tick,
and resets or surges on key events.

---

## Visual Design

```
  HOME                              AWAY
  ◀──────────┤  ●  ├──────────▶
             CENTER
```

- **Bar**: horizontal, full width, color split (home color left, away color right)
- **Indicator** (`●`): a glowing dot that slides left/right
- **Center**: neutral position (kickoff, reset after goal/save)
- **Home attacks**: dot moves RIGHT
- **Away attacks**: dot moves LEFT
- **Near-miss / save**: dot surges to ~80% then snaps back
- **Goal**: dot reaches 100% end with flash animation, then resets

---

## States & Positions

| Event | Dot position | Animation |
|-------|-------------|-----------|
| Kickoff / reset | 50% | instant center |
| Midfield duel | 45–55% | slow drift toward attacker |
| Attack building | 60–70% | medium drift |
| Shot (near_miss / gk_save) | 80–90% | fast surge + snap back |
| Goal | 100% | full surge + goal flash → reset |
| Half-time / full-time | 50% | smooth return to center |
| No event (quiet tick) | previous ± small drift back to 50% | slow decay |

Position is expressed as `0..100` where 50 = center.
Values `< 50` = home attacking (from home's perspective, bar grows LEFT → home's half).

Wait — simpler convention:
- `0` = away team scoring end (home defending desperately)
- `50` = center
- `100` = home team scoring end (away defending desperately)

Home attacks: value increases toward 100.
Away attacks: value decreases toward 0.

---

## Data Source

The attack indicator feeds from **SSE events** already sent by the Go worker,
no additional data needed:

| SSE event type | Effect on bar |
|----------------|---------------|
| `state` with `attack_side = 'home'` | drift toward 100 |
| `state` with `attack_side = 'away'` | drift toward 0 |
| `goal` (home) | surge to 100, flash, reset |
| `goal` (away) | surge to 0, flash, reset |
| `gk_save` / `near_miss` | surge to 80/20, snap to 60/40 |
| `half_time` / `full_time` | animate to 50 |
| `substitution` / `tactic_change` | no change |

If `attack_side` is not in SSE state payload, the bar drifts slowly back to 50.

---

## Go Worker Change (minimal)

Add `attack_side` to the SSE `state` broadcast so the client knows which
team just won the midfield duel:

```go
// In engine/match.go, after resolveTick():
ssePayload["attack_side"] = attackSide  // "home" | "away" | ""
```

No DB change needed.

---

## PHP Fallback (poll-based)

When SSE is unavailable and the client falls back to polling `get-events`,
the bar position is derived from the latest goal event's `team_side`
and recent `gk_save` / `near_miss` events. Less smooth but functional.

### JS State Machine

```javascript
var aiPos = 50;          // current position 0..100
var aiTarget = 50;       // target position
var aiDecayTimer = null; // slow decay back to 50

function setAttackPosition(target, fast) {
    aiTarget = Math.max(0, Math.min(100, target));
    var dot = document.getElementById('ai-dot');
    if (!dot) return;
    dot.classList.toggle('surging', fast);
    dot.style.left = aiTarget + '%';
    aiPos = aiTarget;
}

function attackDecayTick() {
    // Slowly return to 50 if no new events
    if (Math.abs(aiPos - 50) < 1) return;
    var step = (50 - aiPos) * 0.1;
    setAttackPosition(aiPos + step, false);
}

// Called from applyStateTick / processEvent:
function updateAttackIndicator(ev) {
    if (ev.type === 'goal') {
        var end = ev.team_side === 'home' ? 100 : 0;
        setAttackPosition(end, true);
        setTimeout(function() { setAttackPosition(50, false); }, 2000);
    } else if (ev.type === 'gk_save' || ev.type === 'near_miss') {
        var surge = ev.team_side === 'home' ? 82 : 18;
        var rebound = ev.team_side === 'home' ? 62 : 38;
        setAttackPosition(surge, true);
        setTimeout(function() { setAttackPosition(rebound, false); }, 600);
    } else if (ev.type === 'half_time' || ev.type === 'full_time') {
        setAttackPosition(50, false);
    }
}

// From SSE state payload:
function applyAttackSide(side) {
    if (side === 'home') setAttackPosition(Math.min(75, aiPos + 12), false);
    else if (side === 'away') setAttackPosition(Math.max(25, aiPos - 12), false);
}
```

## Acceptance Criteria

- [ ] Static progress bar replaced with attack indicator
- [ ] Dot starts at center on page load / kickoff
- [ ] Dot moves right on home attack events, left on away
- [ ] Near-miss / gk_save: fast surge then snap back
- [ ] Goal: surge to end → goal flash → reset to center (2s)
- [ ] Half-time / full-time: smooth return to center
- [ ] Slow decay toward center when no events arrive
- [ ] Home team color fills left side, away color fills right side (optional)
- [ ] Works in both SSE and poll-fallback modes
- [ ] Mobile: bar remains visible, dot size appropriate
