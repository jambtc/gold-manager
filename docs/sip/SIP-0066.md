# SIP-0066 — Unified Commentary Event Stream

| Field   | Value                 |
|---------|-----------------------|
| Status  | Accepted (Implemented) ✅ |
| Author  | Gold Manager Dev Team |
| Created | 2026-05-21            |

## Summary

Unificare streaming cronaca live in un solo tipo SSE:

- `type: "commentary_event"`
- `phase: "start" | "token" | "done"`
- metadata inclusa (`id`, `event_type`, `minute`, `team_side`, `source`)

Obiettivo: togliere doppio protocollo (`llm_stream_*` + `commentary_stream_*`),
semplificare frontend, mantenere suspense e typing effect.

---

## Problem

Prima del SIP:

- Worker Go emetteva due famiglie eventi:
  - `llm_stream_start/token/done`
  - `commentary_stream_start/token/done`
- Frontend aveva branch duplicati.
- Più rischio di divergenza tra fallback template e LLM.

---

## Event Contract (nuovo unico)

```json
{
  "type": "commentary_event",
  "phase": "token",
  "id": 12345,
  "token": "Le squadre ",
  "description": "",
  "source": "template",
  "event_type": "pre_match",
  "minute": 0,
  "team_side": "home"
}
```

Campi:

- `phase=start`: apre stream per `event_id`
- `phase=token`: append token su stessa riga
- `phase=done`: finalizza testo
- `source`: `template` o `llm`
- `event_type`, `minute`, `team_side`: metadata per UI/debug/analytics

---

## UI Behavior (row per evento)

Regola rendering:

1. Una riga cronaca per `event_id`.
2. Finché arrivano token dello stesso `event_id`, aggiorna la stessa riga.
3. Nuovo evento con minuto diverso crea nuova riga.
4. Più eventi nello stesso minuto: più righe, stesso minuto.

Questo mantiene coerenza con suspense: teaser e reveal restano nella stessa riga.

## Implementation

### Go worker

File: `v2/worker-go/engine/match.go`

- Aggiunti:
  - `commentaryMeta` struct
  - `emitCommentaryEvent(...)` helper
- `enrichEventAsync(...)` ora emette `commentary_event` con `phase`.
- `EnrichPreMatchAsync(...)` idem.
- `streamTemplateText(...)` idem.
- Rimosse emissioni nuove di `llm_stream_*` e `commentary_stream_*`.

### Frontend live

File: `v2/views/fixture/live.php`

- Nuovo handler unico `handleCommentaryPayload(payload)`.
- `EventSource.onmessage` usa prima `commentary_event`.
- Legacy handler `llm_stream_*` / `commentary_stream_*` mantenuti solo come compat layer.

---

## Backward Compatibility

- Frontend continua a capire eventi legacy in caso di worker vecchio.
- Worker nuovo emette solo `commentary_event`.
- `event_update` resta invariato.

---

## Acceptance Criteria

- [x] Un solo flusso attivo lato worker per commentary streaming

- [x] Suspense + typing effect preservati
- [x] Metadata minuto/tipo/squadra disponibile nel payload
- [x] Compatibilità temporanea con stream legacy mantenuta lato frontend
