## Problema

Dopo le correzioni anti-0-0 (SIP-0088), il pendolo ha oscillato all'estremo opposto.

### Dati misurati (`game/batch-friendly 200`)

| Metrica             | Valore osservato | Target    |
|---------------------|------------------|-----------|
| avg gol/partita     | **4.8–5.2**      | 2.5–3.0   |
| 0-0 rate            | 0.5–1.5%         | 5–9%      |
| picco distribuzione | 3–7 gol          | 1–3 gol   |
| max gol (outlier)   | 35               | ≤ 10      |

Serie A reale (riferimento): avg 2.6 gol/partita, 0-0 ≈ 9%.

### Cause identificate

**Go worker** — `baseGoalThreshold = 5.2`:
- P(home goal per tick) = 5.2% × mods ≈ 5%
- 75 tick × 5% × 2 squadre = **7.5 gol attesi** → misurato 4.8 (contenuto dai mods < 1.0)
- Soglia base troppo alta dopo la correzione SIP-0088

**PHP engine** — duel GK troppo facile da battere:
- `gkPower = po * 1.55 + df * 0.2` → GK debole
- `precisionCap` parte da 44 → 44% di ogni tiro supera il GK diventa gol
- Risultato: troppa conversione una volta che l'azione raggiunge il tiro

**Outlier estremi** (35, 26 gol):
- Team senza portiere in formazione → `gkPower = 0` → tutti i tiri entrano
- Mancanza di un floor minimo su `gkPower`

## Soluzione

### Go worker — `baseGoalThreshold`

```
prima:  5.2  →  dopo: 1.8
```

Calcolo obiettivo:
- 75 tick × 1.8% × 2 squadre × mod_medio(~0.95) × pressureMod_medio(~1.05) ≈ **2.7 gol/partita** ✓

### PHP engine — GK power + precision cap

```php
// prima
$gkPower = (int) ($def['po'] * 1.55 + $def['df'] * 0.2);
$precisionCap = min(70, 44 + bonus);

// dopo
$gkPower = (int) ($def['po'] * 1.80 + $def['df'] * 0.25);
$precisionCap = min(65, 38 + bonus);
```

Effetto:
- P(tiro batte GK) scende da ~30% a ~25%
- P(gol alla precision gate) scende da 44% a 38% (inizio partita)
- Gol attesi: ~2.5–3.0/partita ✓

### Floor GK power (outlier fix)

```php
$gkPower = max(80, $gkPower);   // PHP
```

```go
// Go: già protetto da GkHeightMod clamp, ma aggiungere floor al calcolo gkPower
```
