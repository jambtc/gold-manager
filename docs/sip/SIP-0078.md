---

## Obiettivo

Gestire i prestiti in modo realistico:

1. costo prestito più basso della vendita
2. scadenza prestito obbligatoria e precisa
3. rientro automatico al club proprietario con notifica al manager

---

## Problema attuale

- `transfer_type=loan` esiste ma usa logica semplificata
- scadenza legata solo a stagione (`loan_return_season`) e non a timestamp
- rientro non sempre “event-driven” puntuale
- assente notifica manager chiara al rientro

---

## Design funzionale

## 1) Valore economico del loan

Regola:

- `loan_fee` deve essere inferiore al prezzo vendita equivalente
- range suggerito: `10%..40%` di `marketValue(player)`

Formula base:

```text
loan_fee_suggested = round_to_1000(market_value * GM_LOAN_FEE_PERCENT / 100)
```

Vincoli:

- `GM_LOAN_FEE_PERCENT` default `25`
- min `5`, max `50`
- UI mostra hint: “Prestito consigliato: €X (25% valore)”

---

## 2) Scadenza loan

Nuovo campo:

- `transfer.loan_ends_at` (INT unix ts, nullable per sale/free)

Regole:

- obbligatorio se `transfer_type=loan`
- `loan_ends_at > now`
- durata minima: `GM_LOAN_MIN_DAYS` (default 7)
- durata massima: `GM_LOAN_MAX_DAYS` (default 365)

Compatibilità:

- `loan_return_season` mantenuto solo per storico/fallback
- logica runtime usa `loan_ends_at` come fonte primaria

---

## 3) Rientro automatico + messaggio manager

Alla scadenza:

1. player torna a `from_team_id` originario
2. contratto loan chiuso / status aggiornato
3. evento storico trasferimento aggiornato
4. manager proprietario riceve notifica

Notifiche:

- `NewsService` (categoria transfer)
- opzionale `TelegramService` se collegato

Messaggio esempio:

- titolo: `Rientro dal prestito: {player}`
- body: `Il prestito è terminato. {player} è rientrato in rosa da {club_loan}.`

Se manager club loan umano:

- messaggio info “Prestito terminato: giocatore rientrato al club proprietario.”

---

## Trigger/Execution

Approccio valido sia cron che orchestratore:

- job `loan.return.check` ogni 5 min (o orchestrator schedule)
- query prestiti attivi con `loan_ends_at <= now`
- processa in transazione con lock e idempotenza

Idempotenza:

- chiave: `loan-return:{transfer_id}`
- doppio run non deve duplicare rientro o notifiche

---

## Data model

### Modifiche `transfer`

- add `loan_ends_at INT NULL`
- index `idx_transfer_loan_ends_at (status, transfer_type, loan_ends_at)`

---

## API / Controller / UI

### Transfer list modal

- se `loan` selezionato:
  - campo fee prestito
  - campo data scadenza
  - validazione client/server

### Controller

- `actionListPlayer` salva `loan_ends_at` su loan
- `accept-offer` valida che data scadenza sia coerente

### Views

- market: badge “Prestito fino al dd/mm/yyyy HH:mm”
- player/contract view: se in prestito, mostra club e scadenza

- `GM_LOAN_MAX_DAYS=365`
- `GM_LOAN_RETURN_NOTIFY_TELEGRAM=1`

---

## Acceptance criteria

- loan non può avere fee uguale/superiore a sale benchmark
- loan senza `loan_ends_at` non salvabile
- a scadenza giocatore rientra automaticamente
- manager proprietario riceve news rientro
- nessun doppio rientro su run ripetuto
