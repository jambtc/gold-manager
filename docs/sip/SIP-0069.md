# SIP-0069: Internationalization (i18n)

- Status: Draft
- Type: UX / Maintenance
- Created: 2026-05-27

## Abstract

Translate all user-facing strings from Italian to English using Yii2's built-in i18n
system (`Yii::t('app', '...')`). This makes Gold Manager v2 ready for multi-language
support and aligns the codebase with international conventions.

## Motivation

- All views, controllers and components currently contain hardcoded Italian strings.
- English as the base language is standard for OSS and SaaS products.
- Yii2 i18n is already available; no new dependency required.

## Specification

### 1. Configure i18n component

Add to `config/web.php` (and `config/console.php` where applicable):

```php
'i18n' => [
    'translations' => [
        'app' => [
            'class'          => \yii\i18n\PhpMessageSource::class,
            'basePath'       => '@app/messages',
            'sourceLanguage' => 'en-US',
            'fileMap'        => ['app' => 'app.php'],
        ],
    ],
],
```

### 2. Message catalogue

Create `messages/en-US/app.php` returning an empty array (source language = no translation needed).
Create `messages/it-IT/app.php` for Italian translations if needed later.

### 3. Wrap all strings

Replace every hardcoded user-facing string with `Yii::t('app', 'English text')`.

Scope:
- All files under `views/`
- Flash messages in `controllers/`
- Validation labels in `models/`
- Console output in `commands/` (optional / low priority)

### 4. Extraction tooling

Use the Yii message extraction command to find unwrapped strings:

```bash
./yii message/extract config/i18n-extract.php
```

### 5. Naming conventions

- Use natural English sentences as keys (not symbolic keys like `app.team.title`).
- Placeholder syntax: `{name}`, e.g. `Yii::t('app', 'Welcome, {name}!', ['name' => $user->name])`.

## Exclusions

- Log messages and internal debug strings (not user-facing).
- Migration files.
- Strings already in English.

## Acceptance Criteria

- No hardcoded Italian string remains in `views/`, `controllers/`, `models/`.
- `./yii message/extract` reports 0 new unwrapped strings.
- App renders correctly in `en-US` locale.
- Italian locale (`it-IT`) catalogue exists as a stub for future translation.

## Effort Estimate

Large — requires touching every view file. Recommended approach: one view/controller
per PR to keep diffs reviewable.
