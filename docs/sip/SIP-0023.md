## Summary

Enable managers to make real-time decisions during a live match. This requires a "Command Channel" where the PHP frontend sends tactical changes and substitutions to the database, which are then consumed by the Go simulation worker on the next tick.

## Architecture

### 1. The Database Queue
We will use the `match_state` table (or a new `match_command` table) to store pending actions.
- `fixture_id`: Reference to the match.
- `command_type`: `substitution` | `tactic_change` | `intensity_change`.
- `payload`: JSON string containing command details (e.g., `{ "out": 5, "in": 18 }`).
- `executed_at_minute`: The minute the command was processed by the worker (null if pending).

### 2. The PHP Command Controller
A new `LiveActionController` in Yii2 will handle AJAX requests from the `live.php` view.
- `actionSub(fixtureId, playerOutId, playerInId)`
- `actionTactic(fixtureId, newTacticId)`

### 3. The Go Consumer
The Go worker will query the command queue at the start of every tick:
1. Fetch pending commands for the active `fixture_id`.
2. Update the local simulation state (e.g., swap player in the formation).
3. Mark commands as executed in the DB.

## UI Requirements
- Add a "Tactics & Subs" sidebar to the live match view.
- Buttons for quick tactical shifts (Defensive, Balanced, Offensive).
- Drag & Drop or simple dropdowns for substitutions.

## Acceptance Criteria
- [ ] Manager can submit a substitution during a live match.
- [ ] The Go worker reflects the substitution in the next minute's event stream.
- [ ] Tactical changes (e.g., switching to All-Out Attack) modify the engine's win probabilities immediately.
