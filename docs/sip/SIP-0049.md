# SIP-0049 — Friendly Match System (Amichevoli Challenge)

| Field   | Value                 |
|---------|-----------------------|
| Status  | Accepted (Implemented) |
| Author  | Gold Manager Dev Team |
| Created | 2026-05-19            |

## Summary

Replace the current unrestricted friendly simulation with a proper **challenge system**:
- Max **1 friendly per team per week** (midweek, between competitive fixtures)
- Challenge another team → they accept or refuse
- CPU teams evaluate acceptance intelligently (player fatigue, schedule)
- We receive invitations and can accept/decline
- Refused invitations notify the challenger

---

## Rules

| Rule | Value |
|------|-------|
| Max friendlies per team/week | 1 |
| Scheduling window | Wednesday ± 1 day (midweek gap) |
| Challenge expiry | 24h to respond before auto-decline |
| CPU refusal conditions | avg freshness < 70% OR already has a friendly |
| Player fatigue | starters lose −3 freshness (same as competitive match) |
| Stats counted | No — friendlies excluded from standings/marcatori |

---

## DB Schema

New table: `friendly_challenge`

```sql
CREATE TABLE friendly_challenge (
  id              INT AUTO_INCREMENT PRIMARY KEY,
  challenger_id   INT NOT NULL,    -- team that sent the challenge
  challenged_id   INT NOT NULL,    -- team that received it
  status          ENUM('pending','accepted','declined','expired','played') DEFAULT 'pending',
  proposed_date   DATE NOT NULL,   -- proposed match date
  decline_reason  VARCHAR(100) NULL,
  fixture_id      INT NULL,        -- set when accepted and fixture created
  created_at      INT NOT NULL,
  responded_at    INT NULL
);
```

## Challenge Flow

### Sending a Challenge

```
Manager A (Corsa Calcio) → clicks [Sfida a un'amichevole]
  → picks opponent from list (shows availability status)
  → proposed_date auto-set to next Wednesday
  → INSERT friendly_challenge (status=pending)
  → Notification to Manager B: "Corsa Calcio ti sfida a un'amichevole per Mer 22/05"
```

Availability status shown per team:
- ✅ Disponibile
- ⚠️ Potrebbe rifiutare (freshness avg < 75%)
- ❌ Non disponibile (already has a friendly this week)

### Receiving a Challenge (Human Manager)

Notification in news feed (SIP-0050):
```
📬 Invito amichevole
   Fortis Borgo ti ha sfidato per mercoledì 22 maggio.
   [Accetta]  [Rifiuta]
```

- **Accept**: fixture created, both teams notified, simulation queued
- **Decline**: challenger notified "Fortis Borgo ha declinato"
- **No response in 24h**: auto-decline, challenger notified

### CPU Team Response Logic

```php
function cpuDecideFriendly(Team $cpu, FriendlyChallenge $challenge): bool
{
    // Already has a friendly this week?
    if (FriendlyChallenge::hasThisWeek($cpu->id)) return false;

    // Players too tired?
    $avgFreshness = array_sum(array_column($cpu->players, 'freshness')) / count($cpu->players);
    if ($avgFreshness < 70) return false;

    // Random factor: 80% accept if conditions are met
    return mt_rand(1, 100) <= 80;
}
```

Decline reasons (shown in news):
- "I giocatori di {team} sono troppo affaticati"
- "Il {team} ha già un'amichevole in programma"
- "{team} ha preferito riposarsi questa settimana"

## Admin / Testing Mode

Since friendlies are currently open for testing (as noted by user), the admin panel
retains the ability to create instant friendlies bypassing the challenge system.
The `FriendlyController::actionPlay()` (admin path) is unchanged.

The challenge system applies only to the **manager's `/friendly` page**.
