## Obiettivo

Implementare due smart contract su Hyperledger Besu IBFT 2.0:

1. **GoldManagerCoin (GMC)** — token ERC-20 standard, supply fissa 10 B.
2. **GameEconomy** — contratto custom che gestisce le operazioni di gioco on-chain.

## GoldManagerCoin.sol

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import "@openzeppelin/contracts/access/Ownable.sol";

contract GoldManagerCoin is ERC20, Ownable {
    uint256 public constant TOTAL_SUPPLY = 10_000_000_000 * 10 ** 18;

    constructor(address treasury) ERC20("GoldManagerCoin", "GMC") Ownable(treasury) {
        _mint(treasury, TOTAL_SUPPLY);
    }
}
```

Supply fissa: nessun mint post-deploy. Il treasury è un multi-sig controllato dal team.

## GameEconomy.sol

Funzioni principali:

| Funzione                              | Descrizione                                          |
|---------------------------------------|------------------------------------------------------|
| `registerManager(address, teamId)`    | Collega un wallet a un manager nel gioco             |
| `transfer(from, to, amount, reason)`  | Trasferimento GMC tracciato con motivo stringa       |
| `payWage(teamId, playerId, amount)`   | Pagamento salario on-chain                           |
| `recordTransfer(sellerId, buyerId, playerId, fee)` | Registra trasferimento giocatore     |
| `recordSponsor(teamId, amount)`       | Incasso sponsor stagionale                           |

Ogni operazione emette un evento `GameEvent(string category, bytes data)` per audit.

## Deploy

- Rete: Besu IBFT 2.0 privata (vedi SIP-0089).
- Tool: Hardhat + ethers.js.
- Artefatti: ABI + bytecode in `blockchain/artifacts/`.
- Deploy script: `blockchain/scripts/deploy.ts`.

## Test

- Unit test Hardhat per ogni funzione (`test/GoldManagerCoin.ts`, `test/GameEconomy.ts`).
- Test coverage minima: 90%.
