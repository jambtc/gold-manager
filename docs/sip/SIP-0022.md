# SIP-0022 — World Generation and New-Game Seeding

| Field   | Value                     |
|---------|---------------------------|
| Status  | Accepted (Implemented)     |
| Author  | Gold Manager Dev Team      |
| Created | 2026-05-16                |

## Summary

Define the world-generation system that seeds all game data when a new
game instance is created: CPU teams, player rosters with randomised names
and stats, competitions, fixtures, stadiums and staff. Without this, the
application starts with an empty database and is unplayable.

---

## Problem

Phase 3 and Phase 4 delivered models and migrations for teams, players,
competitions, fixtures, contracts, staff and stadiums. No mechanism exists
to populate these tables with a coherent starting world. The legacy codebase
solved this with `crea_squadre.php` (per-team player generation) drawing from
`nomi` and `cognomi` database tables. v2 needs a first-class equivalent that
is repeatable, testable, and driven from a console command.

---

## Scope

| Included | Excluded |
|----------|----------|
| Random team names from a curated list | Logo generation |
| Random player names (first + last) from bundled name lists | Real-world licensed names |
| Position-aware stat distributions per role | Season progression logic |
| Character trait assignment | Transfer market seeding |
| Contract and salary seeding | User account creation |
| Stadium creation per team | Multi-language name pools (future) |
| Competition and fixture generation | |
| One human-controlled team assignment | |

## Architecture

### 1. Entry Point

A single Yii2 console command:

```
./yii game/seed [--teams=16] [--players-per-team=20] [--competition=Serie A]
```

This is idempotent only on an empty database. Running it twice on a
non-empty DB must abort with a clear error.

---

### 2. Name Pool (bundled, no DB tables)

Names are stored as PHP arrays in `components/WorldData.php`, extracted
and cleaned from the legacy `nomi`/`cognomi` tables. No external dependency
(no Faker). Two pools:

- `WorldData::FIRST_NAMES` — ~200 Italian male first names
- `WorldData::LAST_NAMES`  — ~400 Italian surnames

Player full name = `random(FIRST_NAMES) . ' ' . random(LAST_NAMES)`.

---

### 3. Team Name Pool

`WorldData::TEAM_NAMES` — ~60 fictional Italian club names
(e.g. "Atletico Riviera", "FC Montebello", "Unione Castelforte").

The seeder picks `N` names without repetition and creates one `Team` row
per name with `is_cpu = 1`. The human manager's team is created last with
`is_cpu = 0` and `user_id` from the first registered user.

---

### 4. Player Stat Distributions

Each position has a stat profile. Skills are integers 1–99.

| Position | Primary stats (high) | Secondary stats (mid) | Others (low) |
|----------|---------------------|-----------------------|--------------|
| GK       | po                  | rg                    | df, cn, pa, cr, tc, tr |
| DF       | df, tc              | cn, rg                | po, pa, cr, tr |
| MF       | cn, pa              | df, tc, cr            | po, rg, tr |
| FW       | tr, cr              | pa, rg                | po, df, cn, tc |

Stat generation per player:
- Primary stats: `rand(55, 80)` adjusted by a ±5 age modifier
- Secondary stats: `rand(35, 60)`
- Others: `rand(15, 40)`
- `general_skill`: weighted average of all stats (same formula as legacy)
- `form`, `freshness`, `condition`: all start at 100
- `experience`: `rand(5, 40)` weighted by age
- `age`: role-specific range — GK 22–35, DF 20–32, MF 19–31, FW 19–30
- `foot`: 80% right, 15% left, 5% both

---

### 5. Character Trait Assignment

Characters are drawn from the list in `CARATTERI GIOCATORI.txt`. Each
player gets exactly one trait assigned at random with a uniform distribution.

Supported traits (matching `Player::$character` values):

`grintoso`, `ambizioso`, `razionale`, `diligente`, `corretto`,
`duttile`, `inflessibile`, `introverso`, `carismatico`, `popolare`,
`costante`, `irrequieto`

---

### 6. Roster Composition per Team

Default 20-player squad:

| Role | Count |
|------|-------|
| GK   | 2     |
| DF   | 6     |
| MF   | 6     |
| FW   | 6     |

Squad numbers 1–20 assigned in order (GK = 1, 12).

---

### 7. Contracts

For every generated player, one `Contract` row is created:

- `status`: active
- `salary`: derived from `general_skill` (≈ skill × 80 €/month)
- `duration`: `rand(1, 4)` seasons
- `start_season`: 1

---

### 8. Stadium

One `Stadium` per team:

- `name`: `"Stadio di {team_name}"`
- `capacity`: `rand(5000, 25000)` rounded to nearest 500
- `level`: 1

---

### 9. Competition and Fixtures

One `Competition` is created (e.g. "Serie A") containing all seeded teams.
Fixtures are generated as a full double round-robin calendar (home + away
for each pair) using the same `crea_calendario` logic as the legacy codebase.
All fixtures start with `status = SCHEDULED`.

---

### 10. Seeder Class Structure

```
commands/
  GameController.php      ← adds action: actionSeed()
components/
  WorldData.php           ← static name pools, team names, character list
  WorldSeeder.php         ← orchestrates seeding, calls sub-seeders
  seeders/
    TeamSeeder.php
    PlayerSeeder.php
    StadiumSeeder.php
    CompetitionSeeder.php
    FixtureSeeder.php
```

`WorldSeeder::run()` wraps everything in a DB transaction. On failure it
rolls back and prints the error.

---

## Acceptance Criteria

- [ ] `./yii game/seed` on empty DB produces N teams with 20 players each.
- [ ] Every player has a unique full name within the same team.
- [ ] Every player has a character trait from the approved list.
- [ ] Stat distributions respect the position profiles in §4.
- [ ] Each team has exactly one `Stadium` row.
- [ ] One `Competition` exists with one `Standing` row per team.
- [ ] A full double round-robin fixture calendar is generated with `status = SCHEDULED`.
- [ ] All players have an active `Contract` with a non-zero salary.
- [ ] Running the command on a non-empty DB aborts without modifying data.
- [ ] Unit tests cover stat distribution ranges, name uniqueness, roster composition.
