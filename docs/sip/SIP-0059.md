# SIP-0059 — Man-Marking & Zone Marking

| Field   | Value                 |
|---------|-----------------------|
| Status  | Accepted (Implemented) |
| Author  | Gold Manager Dev Team |
| Created | 2026-05-20            |

## Summary

The manager can assign individual man-marks on up to 3 opponent players
before the next scheduled competitive match.
Each marked player suffers a stat penalty during the tick in which the
assigned defender is on the pitch against them.
If no man-marks are set, the team defaults to **zone marking** (current behaviour).

---

## Concepts

| Mode | Description |
|------|-------------|
| **Zona** | No assignments — each defender covers their zone (default) |
| **Uomo** | Up to 3 pairs: my_player_id → opponent_player_id |

Man-marking is per-fixture: it resets when a new fixture is scheduled or
the previous one finishes.

---

## DB Schema

```sql
CREATE TABLE man_marking (
  id              INT AUTO_INCREMENT PRIMARY KEY,
  fixture_id      INT NOT NULL,
  team_id         INT NOT NULL,   -- the team doing the marking
  marker_id       INT NOT NULL,   -- defender assigned to mark
  marked_id       INT NOT NULL,   -- opponent player being marked
  created_at      INT NOT NULL,
  UNIQUE KEY uq_marking (fixture_id, team_id, marker_id),
  UNIQUE KEY uq_marked  (fixture_id, team_id, marked_id)
);
```

Max 3 rows per (fixture_id, team_id).

## Match Engine Effect

In `MatchEngine::computeTeamTotals()`, after computing the defender's
contribution to `totals['df']`:

```php
// Man-marking penalty on the attacker side
$markings = ManMarking::find()
    ->where(['fixture_id' => $fixture->id, 'team_id' => $defTeamId])
    ->all();

foreach ($markings as $marking) {
    // Check if marked player is on pitch (in the attacker formation)
    if ($this->isPlayerActive($attFormation, $marking->marked_id)) {
        // Defender gets a marking bonus (+8% to df)
        $markerBonus = $this->isPlayerActive($defFormation, $marking->marker_id) ? 1.08 : 1.0;
        // Marked attacker loses effectiveness (-12% to attack contribution)
        $totals['df'] = (int)($totals['df'] * $markerBonus);
    }
}
```

Alternatively implemented as: marked player's `tr`/`cr` contribution is
reduced by 12% when the marker is on the pitch.

### Constraints

- Marker must be a DF or DM in the active formation
- Marked player must be a FW or AM in the opponent's formation
- If the marker is substituted off, the marking is void for remaining ticks

## MarkingController

```
GET  /marking/index?fixtureId=X   → view with opponent roster + my markings
POST /marking/assign               → {fixture_id, marker_id, marked_id} → creates row
POST /marking/remove?id=X          → deletes row
```

Access: only the team whose next fixture is fixtureId and match hasn't started.

---

## Opponent Roster Source

Priority order:
1. Latest `scouting_report` for opponent team → use `report_text` JSON
2. Opponent's active `FormationSlot` rows (names/positions, skills obfuscated ±15)
3. Top 11 players by `general_skill` from opponent team

The UI labels unverified players with `~` on stats (same as scout reports).
