# SIP-0061 — Training Statistics & Progress Charts

| Field   | Value                 |
|---------|-----------------------|
| Status  | Accepted (Implemented) |
| Author  | Gold Manager Dev Team |
| Created | 2026-05-20            |

## Summary

A dedicated **Statistiche Allenamento** section (tab in `/training/index`) that
shows daily/weekly skill progression with charts — what improved, by how much,
and compared to the previous week. Per-player and per-stat breakdown.

---

## Data Source

The existing `training_log` table already records every stat gain:

```
id | team_id | player_id | week | season | stat     | xp_gained | new_value | created_at
1  | 3       | 101       | 21   | 1      | skill_tr | 0.08      | 58        | 1716200000
```

**What's missing**: `training_log` stores gains per week, not per day.
A new `training_log_daily` table tracks daily snapshots for the chart.

---

## DB Schema Addition

```sql
CREATE TABLE training_log_daily (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  team_id     INT NOT NULL,
  player_id   INT NOT NULL,
  logged_date DATE NOT NULL,
  -- skill deltas vs previous day (NULL = no change)
  delta_po    TINYINT NULL,
  delta_df    TINYINT NULL,
  delta_cn    TINYINT NULL,
  delta_pa    TINYINT NULL,
  delta_rg    TINYINT NULL,
  delta_cr    TINYINT NULL,
  delta_tc    TINYINT NULL,
  delta_tr    TINYINT NULL,
  delta_form  TINYINT NULL,
  delta_cond  TINYINT NULL,
  general_skill TINYINT NOT NULL,   -- snapshot (for trend line)
  created_at  INT NOT NULL,
  UNIQUE KEY uq_player_date (player_id, logged_date),
  INDEX idx_team_date (team_id, logged_date)
);
```

Migration: `m260520_030000_create_training_log_daily`.

## Population

`EconomyController::actionApplyWeeklyTraining()` already runs Monday.
After updating player stats, write one row per player with the deltas vs
their values from 7 days prior:

```php
// After saving player stats in applyWeeklyTraining():
$yesterday = date('Y-m-d', strtotime('-7 days'));
$prev = TrainingLogDaily::find()
    ->where(['player_id' => $player->id])
    ->andWhere(['<=', 'logged_date', $yesterday])
    ->orderBy(['logged_date' => SORT_DESC])
    ->one();

$row = new TrainingLogDaily();
$row->team_id      = $team->id;
$row->player_id    = $player->id;
$row->logged_date  = date('Y-m-d');
$row->general_skill = $player->general_skill;

foreach (['po','df','cn','pa','rg','cr','tc','tr'] as $s) {
    $field = "delta_{$s}";
    $row->$field = $prev
        ? ($player->{"skill_{$s}"} - ($prev->general_skill /* approx */))
        : null;
}
$row->delta_form = ...; // $player->form - prev->form_snapshot
$row->delta_cond = ...; // $player->condition - prev->condition_snapshot
$row->save(false);
```

Note: a simpler approach is to store the full current values and compute
deltas in the API. See **API** section below.

## Simpler Schema (v2 — preferred)

Store **absolute snapshots** each week, compute deltas on read:

```sql
CREATE TABLE training_snapshot (
  id            INT AUTO_INCREMENT PRIMARY KEY,
  team_id       INT NOT NULL,
  player_id     INT NOT NULL,
  snapshot_date DATE NOT NULL,
  general_skill TINYINT NOT NULL,
  skill_po      TINYINT NOT NULL,
  skill_df      TINYINT NOT NULL,
  skill_cn      TINYINT NOT NULL,
  skill_pa      TINYINT NOT NULL,
  skill_rg      TINYINT NOT NULL,
  skill_cr      TINYINT NOT NULL,
  skill_tc      TINYINT NOT NULL,
  skill_tr      TINYINT NOT NULL,
  form          TINYINT NOT NULL,
  condition_val TINYINT NOT NULL,
  UNIQUE KEY uq_player_date (player_id, snapshot_date),
  INDEX idx_team_date (team_id, snapshot_date)
);
```

Migration: `m260520_030000_create_training_snapshot`.

Weekly cron writes one row per player per `applyWeeklyTraining()` run.
Delta = `current_row.stat - previous_row.stat` (fetched by API).

## API

```
GET /training/progress?playerId=X&weeks=8
```

Returns last N weekly snapshots for a player:

```json
{
  "player": { "id": 101, "name": "Marco Rossi", "position": "MF" },
  "snapshots": [
    {
      "date": "2026-05-13",
      "general_skill": 67,
      "skills": { "po":10, "df":45, "cn":70, "pa":68, "rg":55, "cr":30, "tc":60, "tr":58 },
      "form": 82,
      "condition": 75,
      "deltas": { "general_skill":+1, "cn":+1, "tr":+1, "df":0, ... }
    },
    ...
  ]
}
```

`deltas` = diff vs previous snapshot (null for the oldest).

## UI — Training Tab "Statistiche"

Add a third tab to `/training/index`:

```
[Fisico] [Tattico] [Statistiche ▸]
```

### Team Overview Chart

**Bar chart** (Chart.js) — last 4 weeks:
- X axis: settimana 1…4
- Y axis: general_skill
- One bar series per position group (GK / DF / MF / FW)
- Shows team average improvement trend

### Player Detail

Search/filter by position. Click a player → expand card with:

**Line chart** (8 weeks, one line per skill):
```
        skill_tr ───────────╱
        skill_cn ─────╱─────
        general  ───╱───────
```

**Delta badges** (since last week):
```
  DF  +0    CN  +1 ↑    PA  +0    TR  +1 ↑
  CR  +0    TC  +0       RG  +0    PO  +0
  Forma  −3 ↓   Cond  +2 ↑
```

Green = positive delta, red = negative, gray = zero.

### Top Improvers Widget

"Questa settimana, chi è migliorato di più":

```
🏆  Marco Rossi   MF   +2 skill_tr  +1 skill_cn
    Luca Ferri     DF   +1 skill_df
    ...
```

## Chart Library

Use **Chart.js** (already available or add CDN):

```html
<script src="https://cdn.jsdelivr.net/npm/chart.js@4.4.0/dist/chart.umd.min.js"></script>
```

Render type `line` for player trends, `bar` for team overview.
Dark theme: `backgroundColor: 'rgba(245,158,11,.15)'`, `borderColor: 'var(--gold)'`.

## Cron

The existing `economy/apply-weekly-training` cron (Monday 02:00) writes the
snapshot at the end of training application:

```php
// At end of applyWeeklyTraining() loop, after all players saved:
TrainingSnapshot::writeSnapshot($team->id, $player->id, date('Y-m-d'), $player);
```

No additional cron needed.
