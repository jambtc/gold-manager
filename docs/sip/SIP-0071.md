## 1. Free Agent Pool

- Manager cannot sign directly → must place a bid with amount + expiry datetime.
- Multiple managers can bid on the same player.
- Highest bid at expiry wins → player transferred, others refunded.
- Minimum bid = player's estimated value; raise step = configurable (default 10% or flat €50k).

## 2. Staff Market

- Manager places offer (amount + expiry).
- **Raise button**: one-click to outbid current leader by minimum raise step.
- Staff member hired to highest bidder at expiry.

## 3. Sponsor Market

- Manager places offer for a sponsorship slot.
- Offer includes proposed contract value and expiry.
- Sponsor signed to highest bidder at expiry.

## 4. Auction Auto-Resolution (Cron)

Resolution runs inside `EconomyController::actionApplyDailyTraining`
(also triggered by `economy/apply-daily-training`).

**Rationale — cron over queue:**
- Football manager auctions don't need sub-minute precision.
- Cron container already exists (SIP-0055); no new infrastructure.
- Queue-based delayed jobs add a failure mode: worker restart = unresolved auctions.
- Cron interval 5–15 min is acceptable for this game loop.

Resolution algorithm per auction type:
```
1. SELECT all auctions WHERE expires_at <= NOW() AND status = 'open'
2. For each: find highest bid
3. If winner found: execute transfer/hire/sign, notify winner + losers via Telegram
4. If no bids: re-list or expire silently
5. SET status = 'resolved' | 'expired'
```

## 5. Club Transfer — Indirect Flow (In Progress)

Club-to-club transfers are **always indirect**:

1. Manager A lists their player at asking price → player appears in transfer market.
2. Manager B (or CPU) places a bid → offer stored, Manager A notified.
3. Manager A accepts/rejects.
   - Accept → transfer executes immediately (no auction delay needed).
   - Reject → Manager B can raise or withdraw.
4. **Cooldown**: if no offer accepted, Manager A must wait **48 h** before re-listing
   the same player.

### DB: `transfer_cooldown` table

```sql
CREATE TABLE transfer_cooldown (
    player_id   INT      NOT NULL,
    team_id     INT      NOT NULL,
    unlocks_at  DATETIME NOT NULL,
    PRIMARY KEY (player_id)
);
```

Checked in `TransferController::actionList` before allowing re-list.

### Acceptance criteria

- [ ] Player listed → visible in market for all managers.
- [ ] Bid stored; Manager A receives notification.
- [ ] Accept → transfer executes; cooldown NOT applied.
- [ ] Reject without sale → `transfer_cooldown` row inserted (`unlocks_at = NOW() + 48h`).
- [ ] Re-list blocked if `unlocks_at > NOW()`; UI shows remaining cooldown.

## 6. "Scade tra Xh Ym" Countdown Label

Every auction card (free agent, staff, sponsor) shows a live countdown.

**Implementation:**

PHP renders `data-expires` ISO timestamp on each card:
```html
<span class="auction-countdown" data-expires="2026-05-28T14:30:00Z">
    Scade tra …
</span>
```

JS updates all countdowns every 30 s (no SSE needed for this):
```js
function updateCountdowns() {
    document.querySelectorAll('.auction-countdown').forEach(function(el) {
        var exp = new Date(el.dataset.expires);
        var diff = exp - Date.now();
        if (diff <= 0) { el.textContent = 'Scaduta'; el.classList.add('text-danger'); return; }
        var h = Math.floor(diff / 3600000);
        var m = Math.floor((diff % 3600000) / 60000);
        el.textContent = 'Scade tra ' + (h > 0 ? h + 'h ' : '') + m + 'm';
        el.classList.toggle('text-warning', diff < 3600000); // < 1h → orange
        el.classList.toggle('text-danger',  diff < 900000);  // < 15m → red
    });
}
setInterval(updateCountdowns, 30000);
updateCountdowns();
```

Color coding:
| Remaining | Color |
|-----------|-------|
| > 1h      | muted |
| < 1h      | `var(--gold)` / warning |
| < 15min   | `var(--accent-red)` |
| Expired   | red + "Scaduta" |


simple fetch is sufficient for this update frequency.
