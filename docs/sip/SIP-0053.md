# SIP-0053 — Temporary Manager Test Control: Advance Day

| Field   | Value                 |
|---------|-----------------------|
| Status  | Accepted (Implemented Temporary) |
| Author  | Gold Manager Dev Team |
| Created | 2026-05-19            |

## Summary

Add a **temporary, dev-only** button for managers: `+1 giorno (test)`.

Purpose: accelerate QA for training effects, match history, friendlies, standings,
and season progression without waiting real calendar days.

This feature is explicitly non-production and must have a removal/sunset plan.

---

## Problem

Current scheduling is real-time based (`fixture.match_date` + live worker cadence).
Functional testing of multi-day flows is too slow for single-developer local QA.

---

## Scope

In scope:
- Manager-accessible button in UI (dev/test mode only).
- Server action to advance simulation by exactly one day per click.
- Guardrails to avoid production misuse and race conditions.

Out of scope:
- Permanent gameplay feature.
- Public API exposure.
- Bypassing authorization rules.

---

## Safety Requirements

Feature is enabled only when **all** conditions are true:

1. `YII_ENV_DEV` is true.
2. Env flag `GM_TEST_TIME_TRAVEL=1`.
3. Logged-in user is manager/admin.

If any condition fails, endpoint must return `404` (or `403` for logged users
without permission).

---

## Proposed Design

### UI

- Add button in manager dashboard/tools area:
  - Label: `+1 giorno (test)`
  - Method: `POST`
  - Confirm dialog: `"Operazione test: avanzare di 1 giorno?"`

### Endpoint

`POST /test-time/advance-day`

Controller suggestion: `TestTimeController`.

### Action Flow

1. Acquire short lock (Redis or DB mutex), e.g. `test:advance-day`, TTL 60s.
2. Block if any fixture is currently `PLAYING`.
3. Shift scheduled fixtures by one day earlier:

```sql
UPDATE fixture
SET match_date = match_date - 86400
WHERE status = 0;
```

4. Let Go worker polling pick up newly-due fixtures automatically (5s cycle).
5. Return flash summary:
   - fixtures shifted
   - fixtures due before/after
   - current simulated date delta

### Why this approach

- Minimal invasive change.
- No global rewrite of `time()` calls.
- Works with existing worker and fixture lifecycle.

---

## Risk Analysis

Potential breakage if uncontrolled:
- accidental activation in production
- concurrent clicks while matches are live
- inconsistent expectations between “calendar advanced” and “match fully finished”

Mitigations:
- strict dev flag gate
- lock + no-live-match precondition
- one-day fixed step (no arbitrary jumps)
- explicit temporary status in docs

---

## Sunset / Removal Plan

When QA phase ends:

1. Set `GM_TEST_TIME_TRAVEL=0`.
2. Remove route/controller/view button.
3. Remove SIP status from active backlog or mark as superseded/removed.

No persistent gameplay dependency must remain.
