# SIP-0030 — Manager Friendly Matches & Training + Transfer Windows

| Field   | Value                 |
|---------|-----------------------|
| Status  | Implemented ✅             |
| Author  | Gold Manager Dev Team |
| Created | 2026-05-17            |

## Summary

Two related features:

1. **Manager Friendly Match**: any manager can trigger a weekly friendly
   against a CPU team. The match is simulated instantly. Player stats
   (form, freshness, experience) are updated based on the result.

2. **Transfer Windows**: the transfer market is only open during two defined
   windows per season, matching real football logic.

---

## Part A — Manager Friendly Match

### Motivation

Managers need a way to:
- Test their formation before a competitive match
- Keep player form/freshness high during long fixture gaps
- Earn experience points for young players without competitive stakes

### Rules

| Rule | Value |
|------|-------|
| Frequency | Once per calendar week per team |
| Opponent | Random CPU team from any tier (not from own competition) |
| Result | Simulated instantly by the match engine |
| Standings impact | None — friendly competition, no standings update |
| Budget impact | None — no match revenue, no wage deduction |

### Player Stat Updates (after friendly)

Applied to all players who participated (starting 11):

| Outcome | Form Δ | Freshness Δ | Experience Δ |
|---------|--------|-------------|--------------|
| Win     | +3     | −5          | +2           |
| Draw    | +1     | −3          | +1           |
| Loss    | −2     | −4          | +1           |

All values clamped to [1, 100].
Character traits modify deltas (e.g. *grintoso* gets +2 form on loss).

### Technical Implementation

**Route:** `POST /friendly/play`

**Controller:** `FriendlyController::actionPlay()`

Logic:
1. Check cooldown: one friendly per week per team (store `team.last_friendly_at` timestamp).
2. Pick a random CPU team from another girone.
3. Create a `Fixture` with `competition_id` → "Amichevoli" competition (`type = 'friendly'`).
4. Run `MatchEngine::simulateFull($fixture)` (all 90 ticks in one call).
5. Apply stat deltas to all formation starters.
6. Delete the fixture after stats are applied (or keep for history — configurable).
7. Redirect to a result summary page.

**New field:** `team.last_friendly_at INT NULL` (migration required).

**New method:** `MatchEngine::simulateFull(Fixture $fixture): array` — runs all ticks
  and returns the final event log. Avoids 90 separate DB round-trips by batching inserts.

**View:** `views/friendly/result.php` — scoreline, player stat changes, cooldown timer.

**Cooldown display:** on the dashboard, show "Prossima amichevole disponibile in X giorni"
  if `last_friendly_at > now - 7 days`.

## Part B — Transfer Windows

### Motivation

In real football, the transfer market opens only at specific times.
This prevents managers from buying players at will mid-season and
creates meaningful strategic decisions.

### Window Definitions

| Window | Opens | Closes |
|--------|-------|--------|
| **Pre-season** | Season start (season rollover + 1 day) | Before the first competitive fixture |
| **Winter** | After the last fixture of the first leg (giornata N/2) | Before the first fixture of the return leg |

### Implementation

**Market status** is computed at runtime from the fixture calendar:

```php
class TransferWindowService
{
    public function isOpen(int $competitionId): bool
    // Returns true if now falls within pre-season or winter window for the given competition.
```

Logic:
- **Pre-season open**: `competition.season_start_at <= now <= first_fixture.match_date`
- **Winter open**: `last_first_leg_fixture.match_date + 1 day <= now <= first_return_leg_fixture.match_date - 1 day`
- If no fixtures exist yet (world just seeded): market is open.

**UI enforcement:**
- `TransferController::actionMarket()` checks `TransferWindowService::isOpen()`.
- If closed: show a banner "Mercato chiuso — riapertura il {date}" with a countdown.
- Listing a player and bidding are blocked when closed (HTTP 403 with flash message).
- Admin can bypass the window check (admin flag).

**New table column:** `competition.first_leg_end_date INT NULL` (or computed dynamically
from fixtures — preferred over storing it).

### Window Status Computation (dynamic, no extra column)

```sql
-- First fixture of the season
SELECT MIN(match_date) FROM fixture WHERE competition_id = :cid AND status != 'finished'

-- Last first-leg fixture (round <= total_rounds / 2)
-- Since fixtures are generated in order, the midpoint is round ceil(N*(N-1)/2 / (N/2))
-- Simpler: take the fixture at position COUNT(*)/2 ordered by match_date
```

## Acceptance Criteria

### Friendly

- [ ] `POST /friendly/play` creates a friendly fixture and simulates it.
- [ ] Only one friendly per team per week (cooldown enforced).
- [ ] Form, freshness, experience updated on all starters after match.
- [ ] Result summary page shows score + per-player stat changes.
- [ ] Dashboard shows cooldown countdown.
- [ ] Admin bypass: admin can always trigger a friendly (already implemented via `/admin/friendly`).

### Transfer Windows

- [x] `TransferWindowService::isOpen()` correctly identifies pre-season and winter windows.
- [x] Market listing and bidding blocked when window is closed.
- [ ] Market page shows window status banner with opening/closing dates.
- [x] Admin can always access and operate the market regardless of window.
- [x] Window dates are recomputed dynamically from the fixture calendar — no hardcoded dates.
