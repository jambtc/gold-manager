# SIP-0072 — Repository Migration: gold-manager → gold-manager-v2

| Field   | Value                  |
|---------|------------------------|
| Status  | Accepted (Implemented) |
| Author  | Gold Manager Dev Team  |
| Created | 2026-05-28             |

## Summary

Estrai `v2/` dal repository monolitico `gold-manager` in un nuovo repository
dedicato `gold-manager-v2`, preservando la storia git completa della sottocartella
e abbandonando tutto il codice legacy (`oldGM/`, `newGM/`, `index.php`, ecc.).

---

## Motivazione

Il repo corrente contiene tre generazioni di codice:

| Percorso | Contenuto | Destino |
|----------|-----------|---------|
| `oldGM/` | Prima versione (abbandonata) | Scartato |
| `newGM/` | Transizione intermedia | Scartato |
| `v2/`    | Versione attiva (Yii2 + Go worker) | Nuovo repo |
| `docker/`, `docker-compose.yml` | Infrastruttura v2 | Nuovo repo |
| `docs/`  | SIP e documentazione tecnica | Nuovo repo |

Tenere tutto nello stesso repo inquina la storia, gonfia i clone e crea
ambiguità sul codice canonico.

---

## Procedura di migrazione

### Prerequisiti

```bash
pip install git-filter-repo   # oppure: brew install git-filter-repo
gh auth login                 # GitHub CLI autenticato
```

### Step 1 — Clone di lavoro isolato

```bash
git clone https://github.com/jambtc/gold-manager.git /tmp/gm-migration
cd /tmp/gm-migration
```

> Lavorare su un clone separato: `filter-repo` riscrive la storia in-place
> e non è reversibile sul repo originale.

### Step 2 — Estrai sottocartella `v2/` come root

```bash
git filter-repo --subdirectory-filter v2
```

Dopo questo comando la root del repo contiene direttamente il contenuto
di `v2/` (niente più prefisso `v2/` nei path), con la storia git integra.

### Step 3 — Reinserisci `docker/`, `docker-compose.yml`, `docs/`

Questi file risiedevano nella root del repo originale (fuori da `v2/`) e non
vengono portati da `--subdirectory-filter`. Copiali manualmente dal repo
originale o da `/var/www/gold-manager`:

```bash
cp -r /var/www/gold-manager/docker          /tmp/gm-migration/
cp    /var/www/gold-manager/docker-compose.yml /tmp/gm-migration/
cp    /var/www/gold-manager/start-queue.sh  /tmp/gm-migration/
cp -r /var/www/gold-manager/docs            /tmp/gm-migration/

cd /tmp/gm-migration
git add docker docker-compose.yml start-queue.sh docs
git commit -m "chore: restore docker infra and docs from monorepo root"
```

### Step 4 — Crea il nuovo repo su GitHub e pusha

```bash
git remote remove origin   # filter-repo rimuove già i remote; solo precauzione
gh repo create jambtc/gold-manager-v2 --private --source=. --remote=origin --push
```

### Step 5 — Sostituisci la working directory sul server

```bash
# Backup dell'attuale (opzionale ma consigliato)
mv /var/www/gold-manager /var/www/gold-manager-legacy

# Clone del nuovo repo in produzione
git clone https://github.com/jambtc/gold-manager-v2.git /var/www/gold-manager
```

Aggiorna i path in `docker-compose.yml` se riferiscono a `v2/` come
sottocartella (ora la root IS v2).

### Step 6 — Aggiorna il remote nel repo corrente (opzionale)

Se si vuole continuare a sviluppare da `/var/www/gold-manager` già clonato:

```bash
cd /var/www/gold-manager
git remote set-url origin https://github.com/jambtc/gold-manager-v2.git
```

## File che restano nel vecchio repo (non migrati)

| File/Cartella | Motivo |
|---------------|--------|
| `oldGM/`      | Codice prima versione, archiviato |
| `newGM/`      | Transizione intermedia, archiviato |
| `index.php` (root) | Entry point v1 |
| `Dockerfile` (root) | Dockerfile v1 |
| `mysql/`      | Dump/script DB v1 |
| `images/`     | Asset grafici v1 |
| `CARATTERI GIOCATORI.txt` | Documento design v1 |

Il vecchio repo `gold-manager` può essere archiviato su GitHub
(`gh repo archive jambtc/gold-manager`) dopo aver verificato che
il nuovo repo è operativo.

---

## Acceptance criteria

- [ ] `git log` nel nuovo repo mostra storia di tutti i file con path relativi alla root (non prefissati `v2/`)
- [ ] `docker compose up` funziona dal nuovo repo senza modifiche ai Dockerfile
- [ ] CI/CD (se presente) punta al nuovo repo
- [ ] Vecchio repo archiviato o messo in sola lettura su GitHub
- [ ] `/var/www/gold-manager` sul server punta al nuovo clone

---

## Note

- `git filter-repo` è il successore ufficiale di `git filter-branch` (deprecato).
- La storia del branch `gold-manager-v2` (branch attivo nel vecchio repo)
  viene preservata integralmente per i file sotto `v2/`.
- Dopo la migrazione il branch di default del nuovo repo sarà `main`
  (rinominare da `gold-manager-v2` se necessario con `git branch -m gold-manager-v2 main`).
